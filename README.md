# A 股行业 ETF 轮动策略系统 v0.4

这是一个轻量级、低频、可解释的 A 股行业 ETF 轮动框架。项目优先使用 Tushare 数据，并遵循四个原则：

- 低权限：尽量使用 2000 积分可访问的接口，无法访问时记录问题并降级。
- 低频调用：日线和低频基本面为主，不做高频请求。
- 本地缓存：所有 Tushare 拉取结果缓存到 `data/`，默认不重复请求。
- 可解释回测：输出净值、持仓、换仓、因子得分、窗口回测和 Markdown 报告。

v0.4 的重点不是追求最高收益，而是把“成长、红利、周期”三类资产分开管理，并加入红利相对吸引力、成交额拥挤度和融资风险温度计。

如果只想了解策略如何从市场判断走到最终持仓，请优先阅读：

- [v0.4 策略工作流说明](docs/strategy_workflow_v0.4.md)

如果想从 Python 基础出发，系统学习这套代码如何实现量化策略全流程，请阅读：

- [量化小白代码导读](docs/code_walkthrough_for_beginners.md)

## 当前版本概览

v0.4 的策略结构是：

```text
市场状态分层
  -> 决定成长、稳定红利、周期价值和现金的基础仓位

三风格分仓
  -> 成长池内部轮动
  -> 稳定红利池内部轮动
  -> 周期价值池内部轮动

风格内因子打分
  -> 不同风格使用不同因子

双周再平衡
  -> 降低过度换仓和手续费损耗
```

当前默认回测参数：

| 参数 | 默认值 | 说明 |
| --- | ---: | --- |
| 初始资金 | 1,000,000 | 回测初始现金 |
| 手续费 | 0.0003 | 单边交易成本 |
| 滑点 | 0.0 | 默认不加滑点 |
| 再平衡频率 | biweekly | 每两周调仓一次 |
| 执行价格 | close | 使用调仓执行日收盘价 |
| 每个风格 Top K | 1 | 每个风格池默认选 1 只 ETF |
| 最小调仓偏离 | 0.02 | 目标权重偏离小于 2% 时不交易 |

## 三层框架

系统仍保留最初的三层设计：

```text
日 K 线：决定趋势、动量、轮动排序、市场状态和目标仓位。
基本面：只做行业偏好修正和风险过滤，不单独触发买入。
60 分钟 K 线：预留为执行过滤，不负责重新选择行业。
```

v0.4 默认 `use_intraday: false`。60 分钟模块保留接口，但默认关闭，避免在时间对齐没有完全验证前引入未来函数风险。

## ETF 池与风格分类

ETF 池在 `config.yaml` 中手工维护。每只 ETF 至少包含代码、名称、主题、风格、申万行业映射和是否启用基本面。

v0.4 使用三类风格：

| 风格 | 定位 | 当前包含方向 |
| --- | --- | --- |
| `growth` | 高弹性成长资产 | 医药、半导体、芯片、人工智能、军工、新能源车、光伏 |
| `stable_value` | 稳定红利和防守资产 | 银行、消费、电力、红利 |
| `cyclical_value` | 周期价值和顺周期资产 | 证券、地产、有色、煤炭、钢铁 |

如果某只 ETF 数据不可用，程序会自动跳过，不会让回测崩溃。

## 市场状态分层

市场状态分为四档：

| 状态 | 含义 |
| --- | --- |
| `strong` | 指数趋势、市场宽度和结构行情较强 |
| `neutral` | 市场不弱，但趋势或宽度没有全面确认 |
| `weak` | 市场偏弱，降低成长和周期仓位，提高红利/现金 |
| `crisis` | 风险状态明显，显著提高现金仓位 |

市场状态由以下信息综合判断：

- 指数趋势：沪深300相对 MA60、MA120、MA250 的位置。
- ETF 宽度：ETF 池中收盘价高于 MA60 的比例。
- 回撤风险：沪深300近 60 日最大回撤。
- 结构行情：Top3 ETF 的 60 日收益、正收益 ETF 占比、相对沪深300超额收益。
- 融资风险：Tushare `margin` 融资余额分位；若融资余额高分位且指数跌破 MA20，视为杠杆过热后转弱。

基础风格仓位：

| 市场状态 | 成长 | 稳定红利 | 周期价值 | 现金 |
| --- | ---: | ---: | ---: | ---: |
| strong | 50% | 35% | 15% | 0% |
| neutral | 25% | 55% | 10% | 10% |
| weak | 5% | 70% | 5% | 20% |
| crisis | 0% | 45% | 0% | 55% |

仓位还会做两类修正：

- 如果结构行情成立，中性或弱市场可以适度提高成长/周期卫星仓位。
- 如果融资风险较高，降低成长和周期价值仓位，提高现金或稳定红利仓位。

## 风格内轮动因子

所有风格内因子在同一调仓截面内做 z-score 标准化后加权。正权重表示越高越好，负权重表示越高越需要惩罚。

### 成长池因子

| 因子 | 权重 | 方向 | 解释 |
| --- | ---: | --- | --- |
| `ret_60` | 0.25 | 越高越好 | 近 60 日收益，中期动量核心。 |
| `ret_120` | 0.15 | 越高越好 | 近 120 日收益，确认中长期趋势。 |
| `ret_20` | 0.10 | 越高越好 | 近 20 日收益，捕捉近期强度。 |
| `relative_ret_60` | 0.15 | 越高越好 | ETF 近 60 日收益减沪深300近 60 日收益。 |
| `trend_structure` | 0.15 | 越高越好 | 均线结构是否健康，例如短均线强于长均线。 |
| `vol_20` | -0.10 | 越低越好 | 近 20 日年化波动率，惩罚高波动。 |
| `premium_20` | -0.10 | 越低越好 | 当前价格相对 20 日均线偏离度，避免追高。 |
| `amount_crowding` | -0.05 | 越低越好 | 近 20 日成交额相对近 120 日成交额的放大程度。 |
| `valuation_percentile` | -0.05 | 越低越好 | 成长资产估值过高时小幅扣分。 |

### 稳定红利池因子

| 因子 | 权重 | 方向 | 解释 |
| --- | ---: | --- | --- |
| `dividend_yield_abs` | 0.15 | 越高越好 | 成分股加权估算股息率的绝对水平。 |
| `dividend_yield_percentile` | 0.15 | 越高越好 | 股息率相对自身历史或同类的分位。 |
| `dividend_spread` | 0.20 | 越高越好 | 股息率减 10 年国债收益率，衡量红利相对吸引力。 |
| `dividend_spread_percentile` | 0.15 | 越高越好 | 红利利差的历史分位。 |
| `valuation_score` | 0.15 | 越高越好 | PB/PE 自身历史分位换算后的估值得分。 |
| `ret_60` | 0.05 | 越高越好 | 保留少量中期动量，避免买入持续走弱资产。 |
| `vol_20` | -0.10 | 越低越好 | 红利资产也要控制短期波动。 |
| `drawdown_risk_60` | -0.05 | 越低越好 | 近 60 日最大回撤风险。 |

### 周期价值池因子

| 因子 | 权重 | 方向 | 解释 |
| --- | ---: | --- | --- |
| `ret_60` | 0.20 | 越高越好 | 周期资产更依赖趋势确认。 |
| `ret_120` | 0.15 | 越高越好 | 确认周期趋势的持续性。 |
| `relative_ret_60` | 0.20 | 越高越好 | 是否明显跑赢沪深300。 |
| `valuation_score` | 0.15 | 越高越好 | 估值越便宜得分越高。 |
| `dividend_yield_abs` | 0.05 | 越高越好 | 周期资产可少量参考股息率。 |
| `vol_20` | -0.10 | 越低越好 | 惩罚短期高波动。 |
| `drawdown_risk_60` | -0.10 | 越低越好 | 周期资产回撤惩罚更重。 |
| `amount_crowding` | -0.05 | 越低越好 | 成交额拥挤时降低追入意愿。 |

## 基本面与红利数据

v0.4 的基本面是辅助模块，不单独触发买入。技术面明显走弱的 ETF，即使基本面较好，也不会被强行买入。

数据优先级：

1. 使用跟踪指数成分和权重。
2. 如果没有跟踪指数，使用申万行业成分。
3. 如果成分股不可用，使用 `config.yaml` 中的手工降级分数或股息率。
4. 如果以上都不可用，则关闭对应基本面因子。

当前实现重点：

- 使用 `daily_basic` 获取成分股 `dv_ttm`、`pb`、`pe_ttm`、`circ_mv`。
- 使用成分股权重或市值权重估算 ETF/行业股息率、PB、PE。
- 估值使用自身历史分位，而不是直接跨行业比较。
- 红利相对吸引力使用 `股息率 - 10年国债收益率`。
- 10 年国债收益率来自 Tushare `yc_cb`，按月低频获取并缓存，避免频繁调用限额。

为什么估值看自身历史分位：

```text
银行长期低 PB，半导体长期高 PE。
如果直接跨行业比较 PE/PB，会天然偏向银行、煤炭等低估值行业，
但这不一定代表更好的风险收益。
```

所以 v0.4 采用“行业相对自身历史是否贵/便宜”的方式，降低行业天然估值差异的干扰。

## 数据、缓存与降级

Tushare token 只从环境变量读取，不能硬编码：

```powershell
$env:TUSHARE_TOKEN="你的 token"
```

如果你使用本机 VPN 或代理，当前默认端口是 7890：

```powershell
$env:TUSHARE_PROXY_URL="http://127.0.0.1:7890"
```

`config.yaml` 里也已经配置：

```yaml
proxy_url: "http://127.0.0.1:7890"
```

所有 API 结果默认缓存到 `data/`。除非显式传入 `--refresh` 或修改脚本，否则不会重复请求 Tushare。

常见降级逻辑：

- ETF 日线不可用：可使用 `data/local_csv/` 下的本地 CSV。
- 60 分钟数据不可用：自动关闭 60 分钟执行过滤。
- 基本面数据不可用：关闭对应因子，或者使用手工配置降级。
- 债券收益率或融资数据不可用：记录到 `outputs/*_issues.csv`，并使用中性值继续运行。

## 运行方式

安装依赖：

```bash
pip install -r requirements.txt
```

权限检测：

```bash
python scripts/check_tushare_access.py
```

运行主回测：

```bash
python scripts/run_backtest.py
```

也可以使用：

```bash
python main.py
```

生成窗口回测和因子解释：

```bash
python scripts/window_backtest_analysis.py
```

```bash
python -m pytest -q
```

## 当前局限性

- 回测结果尚未做训练集/测试集切分，不能据此做参数寻优。
- ETF 池仍是手工维护，行业映射可能不完美。
- 部分 ETF 的跟踪指数成分不可得时，会使用申万行业或手工分数降级。
- 财务类因子没有完整启用 point-in-time 财报生效逻辑，因此 v0.4 更偏重估值、股息率和市场交易数据。
- 60 分钟执行过滤默认关闭，尚未严格验证调仓时点与 60 分钟 K 线完成时间的对齐。
- 当前策略在 2024-2025 的进攻性不足，后续需要针对强市场暴露做专门迭代。

## 后续迭代方向

可能的 v0.5 方向：

- 改进强市场识别，避免在趋势行情中过早偏向防守。
- 对成长池增加更适合 A 股结构行情的行业扩散、涨停热度或指数相对强度确认。
- 对稳定红利池区分“真红利”和“周期高股息”，避免煤炭、有色等周期品在价值池中过度占优。
- 增加窗口回测评价，不只看全区间收益。
- 增加参数冻结机制，任何参数优化都必须做训练/测试集拆分，避免数据挖掘。

## 常见问题

### 为什么输出 CSV 字段有英文？

底层 CSV 保留英文字段名，方便程序读取、回归测试和后续迭代。Markdown 报告会尽量使用中文说明。如果需要，也可以进一步把报告层表格列名全部中文化。

### 为什么 PowerShell 里中文有时乱码？

这是终端显示编码问题，不代表文件损坏。项目输出文件使用 UTF-8 或 UTF-8-SIG 编码，建议用编辑器或 Excel 打开 CSV/Markdown 查看。

### 为什么 Tushare 有时连不上？

常见原因是 Codex 沙箱或本机网络代理。当前项目支持通过 `TUSHARE_PROXY_URL` 或 `config.yaml` 的 `proxy_url` 走 `127.0.0.1:7890`。如果仍失败，可以先运行：

```bash
python scripts/diagnose_tushare_network.py
```

### 如果 Tushare 权限不足怎么办？

程序不会为了缺少某个低频接口直接崩溃。它会记录问题，使用缓存、手工配置或关闭对应模块。只有 ETF 日线等核心价格数据完全不可用时，才需要提供本地 CSV 或检查 token/网络。
